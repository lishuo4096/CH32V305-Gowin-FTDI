# 实板验证记录

记录日期：2026-11-11。目标为 GW1N-9C，IDCODE `0x1100481B`，使用 Gowin V1.9.12.02 SP2、CH32V305GBU6 144MHz、USB 分析仪和 100MS/s 逻辑分析仪。

## 嵌入式 Flash 升频

同一份 `07_LED_Flow/impl/pnr/LED_Run.fs`，SecurityBit ON，User Code `0x0000A9D4`。输入 SHA256：


该 FPGA 例程文件没有打包进本仓库。测试通过官方 CLI 的 operation_index 6 执行完整 embFlash Erase,Program,Verify，以完整 Verify Success、原生退出码和错误文本判定。下表为无 Frida、无分析仪启动等待门控的原生测试；同时运行硬件 USB 抓包。

最后已在 2.5MHz 连续两次擦除、编程、校验成功，保留原 LED 例程。本轮未执行断电重启验证。建议当前 Flash 工作档为 2.5MHz；有限样本不构成长时间稳定性证明。首次 2.5MHz 也有一次内部擦除重试。

## 观测影响

另一次 `flash_3MHz` 在 IR75 前暂停 FT_Write、等待逻辑分析仪启动，结果擦除失败；该等待改变目标时序，因此不计入原生通过率。

`diagnostic_3p333333MHz` 使用不显式暂停目标的 Frida 异步观测，完整校验通过，报告 24.55 秒。它仍有观测开销，不能与原生记录混为同一条件。软件采集只保留到第一个 IR71 编程页，完整校验依据为高云软件自己的 Verify Success。

编程窗口 TCK 周期主要为 30/31 个 100MS/s 采样点，符合约 3.27MHz。标为 erase 的异步窗口已经包含大量编程波形，且缺少结束元数据，不能证明完整擦除时钟连续性。原始大体积波形和 USB 抓包留在本地调试归档，不在 Git 仓库中；本仓库保留可直接阅读的终端日志。

3.75MHz 及以上未执行本轮 Flash 测试。结果不能解释为确定的电气频率极限，也不能直接归因于更高档位的大命令分段。

## GAO 与 SRAM

低速 GAO 使用 50MHz 采样时钟、1024 深度、25 位计数器与 LED 关系验证。原生 GUI 导出 7 组有效 CSV；随后固定事务回放在 2.5MHz 请求档执行 100 次独立打开/采集/关闭，102,400 个样本全部通过，严格检查环形缓存次序、计数连续性及 LED 关系。

进一步回放测试：2.5MHz 档 10 次，3.75/5/7.5/10/15MHz 各 100 次，随后原生 SRAM 下载检查后额外采集，共计 541 次、553,984 个样本通过。各升频阶段的逻辑窗口均观测到预期的 33,092 个 TCK 上升沿；实际批量 SPI 为 2.25/4.5/4.5/9/9/18MHz。

原生 SRAM 下载同一 GAO 镜像：5MHz 请求约 2.73 秒、10MHz 约 2.32 秒、15MHz 约 2.35 秒，均成功，随后各 10 次采集通过。此前低速 SRAM 独立校验也已通过。这些测试对应 GAO/SRAM 路径，不能证明 Flash 在相同请求档可用。

发布前从当前源码在独立输出目录全量重建，要求退出码 0、零错误、零告警。新 BIN 与本轮实板使用的归档 BIN 逐字节比较一致。`firmware/` 发布的是原先经过实板验证的 ELF/HEX/BIN，文件哈希见 SHA256SUMS.txt。

根目录的实验备份、外部参考项目、构建缓存和原始大文件未提交，发布没有修改 MCU 源码或重烧硬件。
