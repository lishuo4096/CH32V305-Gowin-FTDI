# 当前实现与时钟路径

发布快照保留当前实板验证代码，不对升频失败作未经验证的修复。

## 主机到执行器

高云软件通过 FTDI D2XX 驱动提交控制请求与 MPSSE 字节流。USBHS OUT 接收后由 FTDI 通道缓冲送入 MPSSE 解析器；解析器维护当前 TAP/IR 状态，选择 GPIO、SPI 或 TIM/DMA 路径。读回数据经过 FTDI 每包两字节状态前缀封装后从 IN 端点返回。

通道 A 为 JTAG；通道 B 桥接 USART3。USB 接收和 JTAG 执行共用有限 RAM，长事务不能简单放入一块与输入等大的缓冲。

## 三条时钟路径

| 路径 | 用途 | 当前特点 |
|---|---|---|
| GPIO | TMS、位操作、短命令 | 软件产生，速度与 SPI 不完全一致 |
| SPI1 + DMA | 较长字节移位、适用的 Run-Test/Idle | 144MHz APB2 整数二次幂分频；0.5625/1.125/2.25/4.5/9/18MHz |
| TIM1 + 双 DMA | IR71 Flash 单字完整事务 | 144MHz 整数分频；请求被限制在最高 4MHz |

MPSSE `0x8A` 关闭五分频时，请求 TCK 为 `30MHz/(divisor+1)`；`0x8B` 开启五分频时为 `6MHz/(divisor+1)`。这只是请求值，各执行路径仍受自身分频与执行开销约束。

## Flash 单字事务

对已识别的 IR71 编程流程，缓存进入 Shift-DR、32 位数据、退出、Update-DR、Idle 和后续 Run-Test 时钟，尽量让同一个字的事务在硬件节拍下连续执行，减少 USB 包边界和软件解释带来的停顿。缓存容量为 128 位波形事件。

TIM1 Update 请求 DMA1 通道 5，写 GPIOA BSHR 驱动 TCK/TDI；TIM1 CC1 请求 DMA1 通道 2，写 GPIOB BSHR 更新 TMS，较 Update 延后一拍。完成后恢复 SPI RX 相关 DMA 配置。USB 中断在波形 DMA 运行时保持工作，避免长时间屏蔽中断造成接收丢失。

TIM 半周期 tick 数取 `round(144MHz / (2 × requested_rate))`，所以请求 2.5MHz 实际约 2.482759MHz，请求 3.333333MHz 实际约 3.272727MHz。系统时钟仍为 144MHz。

## 擦除连续时钟

仅在已知 TAP Idle、IR75、只写、长度处于现有边界范围的命令下启用连续输出特例。使用固定内存发出所需时钟，再消费其余主机占位数据，避免 USB 分块把必要的时钟串拆散。当前长度判断为 8000～65535 字节；更长命令不使用此特例。

本轮原生失败已经发生在低于上述长度上限的档位，因此不能把未测试的 65536 字节分段问题直接当作本轮失败根因。

## 仍需解决的问题

3MHz 请求下完整流程偶发擦除失败；3.333333MHz 原生失败但带观测又曾通过，表明测量开销和时序变化需要纳入对照。当前证据不能确定主机调度、固件状态切换、连续擦除时钟或板级时序各自的责任。

后续应先取得不暂停目标且能覆盖完整擦除过程的成功/失败波形，再比较 IR75 前置配置、连续时钟与后续状态读取。GAO 的高吞吐 SPI 路径不等于 Flash 单字事务和擦除流程已能同速工作。
